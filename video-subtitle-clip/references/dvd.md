# DVD 소스 — VOB 이어 읽기 · 인터레이스

SKILL.md 1단계에서 소스가 DVD(VOB)일 때 읽는다.

### 1-b. DVD VOB — 조각내지 말고 이어서 읽는다

`VTS_xx_1.VOB`·`VTS_xx_2.VOB` 처럼 번호가 붙은 파일은 **하나의 영상이 잘려 있는 것**이다. DVD 규격이 파일 하나를 1GB로 제한해서 생긴 분할일 뿐, 내용은 이어진다. DVD 플레이어는 이 파일들을 따로 열지 않고 **바이트를 이어 붙여 하나의 연속 스트림으로 읽는다.** 그래서 경계를 걸친 GOP도 온전히 디코딩되고 오디오도 끊기지 않는다.

**파일별로 디코딩해서 결과를 이어붙이면 반드시 실패한다.** 경계에서 정지 프레임이 생기고, 오디오 시작 타임스탬프를 손으로 맞춰야 하며, 그 보정이 또 다른 어긋남을 만든다. 실제로 그 길을 갔다가 이음매 하나 때문에 여섯 번을 다시 렌더한 적이 있다.

**올바른 절차** — 두 파일에 걸친 구간을 뽑을 때:

```bash
# 1. 앞 파일의 꼬리만 바이트째 떼어낸다 (2048 = DVD 팩 크기, 반드시 정렬)
dd if=VTS_05_2.VOB bs=2048 skip=<시작팩번호> of=tail.vob

# 2. 뒤 파일과 이어 붙인다 — 플레이어가 읽는 것과 같은 스트림이 된다
cat tail.vob VTS_05_3.VOB > seam.vob
```

떼어낼 위치는 원하는 지점보다 넉넉히 앞(1분쯤)에서 잡는다. 바이트 오프셋 = `파일크기 - 여유초 × 비트레이트/8`, 이를 2048로 내림 정렬한다.

**시각 탐색이 안 된다는 점이 중요하다.** VOB는 PTS가 깨져 있어(`ffprobe` 가 길이를 26시간으로 읽는 일이 흔하다) `-ss` 가 먹히지 않는다. 이어붙인 파일은 더 심하다. 그래서 원하는 프레임을 **찾아야** 한다:

```bash
# 기준 프레임(원본 파일에서 -ss 로 뽑은 것)과 대조해 위치를 특정
# seam.vob 앞부분을 fps 필터로 훑으며 상관계수 최대 지점을 찾는다
```

찾은 시각으로 **`trim` 필터**를 쓴다. `trim` 은 디코딩된 프레임 위에서 동작하므로 탐색이 필요 없다. `-ss` 대신 `trim=start=N` 을 쓰는 것이 핵심이다.

이렇게 하면 이어붙이는 작업 자체가 사라지므로, A/V 동기도 손댈 필요가 없다. 스트림이 원래 맞아 있다.

**분할 VOB 하나만 자를 때 (`VTS_xx_3.VOB` 단독)**

분할 파일은 타임코드가 0이 아니라 앞 파일에서 이어진 값으로 시작한다(실측 `start_time=3261`, 54분). 사용자가 말하는 「23:04」는 **그 파일 안에서의 위치**다(파일 길이 27분이라 절대 시각일 수가 없다).

🔴 **ffmpeg 는 이미 파일 시작을 0초로 맞춰 읽는다** — 영상·음성에서 같은 값을 빼주므로 둘 사이 차이(실측 0.34초)도 보존된다. 여기서 `start_time` 을 한 번 더 빼면 전부 음수가 돼 **출력이 비고**(261바이트, `No filtered frames`), 영상·음성을 `PTS-STARTPTS` 로 각각 0에 맞추면 그 0.34초가 사라져 **입이 안 맞는다.** 둘 다 같은 상수만 뺀다:

```bash
-vf "trim=start=1384:end=1604,setpts=PTS-1384/TB,bwdif=mode=1:parity=1,..."
-af "atrim=start=1384:end=1604,asetpts=PTS-1384/TB,..."
```

⚠️ 타임코드 연속성을 `ffprobe -show_entries packet=pts_time` 으로 볼 때, **B프레임은 표시 시각이 비어 있다.** 빈 값을 0으로 읽으면 가짜 「끊김」이 수만 개 나온다. 숫자인 줄만 센다.

### 1-c. 인터레이스 — 스케일 전에 반드시 푼다

DVD(NTSC)는 대부분 인터레이스다. 한 프레임을 위아래 필드로 쪼개 초당 60번 번갈아 그리는 방식이라, 그대로 확대하면 움직임마다 빗살이 생기고 **끊기는 것처럼 보인다.** DVD 플레이어는 이걸 자동으로 풀어주므로 원본은 멀쩡해 보인다 — 내 결과물만 끊긴다면 십중팔구 이것이다.

```bash
ffprobe -v error -select_streams v -show_entries stream=field_order -of default=noprint_wrappers=1 IN
ffmpeg -ss 60 -i IN -frames:v 300 -vf idet -f null - 2>&1 | grep "Multi frame"
```

`field_order=bb`(BFF) 또는 `tt`(TFF)이고 `idet` 가 BFF/TFF 를 세면 인터레이스다.

```bash
-vf "bwdif=mode=1:parity=1,hqdn3d=3:2:4:4,scale=1440:1080:flags=lanczos,setsar=1,pad=1920:1080:240:0:black,ass=cut.ass"
```

`parity` 는 `0`=TFF, `1`=BFF. `mode=1` 은 필드마다 한 장을 만들어 59.94fps 로 낸다 — 움직임이 가장 부드럽고 DVD 플레이어가 보여주는 것과 같다. **디인터레이스는 스케일보다 반드시 앞**에 온다. 순서가 바뀌면 필드가 섞인 채 확대돼 되돌릴 수 없다.
